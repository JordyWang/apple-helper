# Apple 日程与待办

把自然语言需求转成对 `apple-helper` 的查询和操作。MCP 承担数据访问与参数校验；本技能负责选择事项、理解时间、规划步骤及核对结果。用户的明确指令和已有偏好优先，不把本次选择自动记成长期偏好。

## 连接与定位

- 发现服务器 `apple-helper` 的工具；宿主可能给工具名加前缀，以当前工具目录为准。不要改用名称相似的 Google Calendar 工具。
- 首次使用或权限报错时调用 `get_status`，取得权限和 Mac 时区。用户已要求连接本地应用时，可按需调用 `request_access` 请求所缺权限。
- 如果 MCP 尚未载入，说明需要在客户端的 MCP 设置中重启 `apple-helper`。不要假装已操作，也不要为执行普通日程任务重新安装服务或更改权限策略。
- 首次规划或新建前调用 `get_preferences`，读取有效默认列表/日历、时区、工作时间和常用时长。本次指定目标优先；没有指定目标时，可省略容器 ID，由 MCP 使用已保存偏好，再回退到 macOS 默认值。只有默认目标缺失或无效时才询问目标；不要将列表中的第一项当作默认值。
- 用户明确说“以后默认…”“记住我的工作时间…”时，用 `update_preferences` 保存相应字段；传刚读取的偏好 `version` 为 `expected_version`。`null` 恢复该字段的系统默认或未设置状态。仅当用户指定名称时，查询容器列表取得真实 ID，并区分同名的不同账户。

## 将意图映射到操作

| 用户意图 | 做法 |
| --- | --- |
| 查看今天、本周或某天 | 优先用 `get_agenda` 取得日程和到期、逾期、无日期待办，跟随分页呈现 |
| 加一件待办、届时提醒我 | 创建提醒事项；带通知意图且时间明确时同时设置 `alarms` |
| 安排会议、占用一段时间 | 创建日程，确定开始和结束时间，并检查该时段的日程 |
| 找时间处理待办 | 用 `find_free_slots` 计算窗口，再结合待办提出时段；授权写入后创建日程 |
| 改期、移动、改内容 | 日程改期优先用 `reschedule_event` 检查冲突；其他修改使用对应更新工具 |
| 做完了、恢复未完成 | 对匹配提醒设置 `completed: true/false` |
| 删除、取消指定日程 | 定位对象和重复范围，再调用相应删除工具 |

“查看、总结、整理、规划建议”通常只需读取和提出方案。“按你判断直接安排”“把这些写入日历”等已授权操作应继续执行，不再重复索要批准。若“清理”“整理”到底指删除还是分类不明确，先给出匹配项和具体可选处理方式，再澄清这一点。

## 查询、概览与规划

- 将日期解释为用户当前时区的实际日期，优先用户明确时区和客户端时间上下文；仅在缺少这些信息时使用 `get_status` 的时区。不要拿执行环境的 UTC 日期当作“今天”。
- 日程使用 `[start, end)`，查询一天时采用当天午夜至次日午夜。每次最多 366 天；更长区间分段，按 ID 和 `occurrence_start` 去重。跟随 `next_offset` 读取完成当前请求所需的页数，不能把第一页说成全部结果。
- 今日待办通常查询 `completed: false`：到期日在今日之前的是逾期项，今日到期的是今日项。只查有日期事项时不要把无日期待办说成不存在；需要完整盘点时再取无日期项。查询优先限定相关列表、日期或关键词。
- `list_reminders` 的返回顺序不是优先级。概览可按已排定日程、今日截止、逾期和其他待办组织；依据实际日期、优先级和用户上下文排序，不虚构紧急程度。
- 找空闲时间使用 `find_free_slots`，覆盖相关日历。它会合并忙碌区间、排除 free/取消事件并应用缓冲。全天事件默认计入占用；按用户意图明确选择 `all_day_policy`，遇到节假日、生日可说明是否忽略。返回的是可用窗口及首个建议时段，提醒事项本身不占用日历。
- 规划时保留既有约会，优先使用用户已保存的 `work_hours` 和 `event_duration_minutes`。有时长偏好时，新建普通日程可省略结束时间；没有则确定具体时长。缺少参数时，可在建议中列出假设；用户授权自主安排时采用合理默认并说明，关键参数无法确定时只询问必要信息。
- 把提醒安排进日历，不代表提醒已完成。除非用户要求，不删除原提醒、不标记完成。“会议前提醒我”直接使用日程原生通知，无需再创建一份提醒事项；只有用户同时需要待办记录时才创建两个对象，并分别记录结果。

## 时间与写入细节

- 写入时间戳必须带偏移或 `Z`，`time_zone` 使用 IANA 名称；显示时转换回用户时区。遇到跨时区或夏令时歧义，不猜不存在或重复的本地时刻。
- “周五前做完”用 `due_date` 表示日期；“周五 18 点提醒我”使用 `due_at` 与绝对通知 `alarms: [{type: "absolute", at: "带时区时间戳"}]`。`due_at` 不会自动触发通知，两个到期字段不可同时传入。
- “会议前 10 分钟提醒”用 `alarms: [{type: "relative", offset_minutes: -10}]`，可传多个通知。提醒事项的相对通知必须有具体时间的 `due_at`，服务会将它转成对应绝对时间；全天提醒使用绝对通知。
- 改期默认保持所有通知：相对通知保留提前量，绝对通知按日程开始/提醒到期时间的变化同步移动。用户明确要求通知时间不变时传 `alarm_policy: "preserve"`。省略 `alarms` 表示保留，传数组表示完整替换，`alarms: []` 清空。只改备注等无关字段不会移动通知。
- 全天日程必须使用 Mac 当前时区的午夜，结束时间为下一天午夜且不含该日；用户时区与 Mac 不一致时说明这一限制。不要将 UTC 的 00:00 当作当地午夜。
- 改期日程只传新 `start` 时保持时长，全天事项保持日历天数。`reschedule_event` 默认拒绝冲突，只有用户确实允许重叠才用 `conflict_policy: "allow"`；重复系列的冲突检查仅覆盖选定实例，不代表后续全部无冲突。普通与全天互转时给出起止边界。
- `notes: ""` 清空备注；`due_at: null` 或 `due_date: null` 清到期日；`alarm_at: null` 清通知。省略字段才表示保留原值。

## 唯一匹配、重复事项与核对

- 修改、完成或删除前，用列表查询定位，再用 `get_reminder` / `get_event` 读取对象，将返回 `version` 原样传为 `expected_version`。出现同名多项时依据列表/账户、日期和备注消歧；仍有多项符合时让用户选择，不对所有同名项执行。
- 重复日程必须传列表结果中的 `occurrence_start`，默认 `scope: "this"`。用户要求“这次及之后”用 `future`；要求当前整个系列时先 `get_event_series`，使用其版本和 `scope: "all"`。系列分段、重复规则与恢复细节见 [高级操作](references/advanced.md)。
- 重复提醒的完成、修改或删除需要 `allow_recurring: true`。完成后系统可能将原 ID 用于下一次；若响应包含 `next_occurrence`，分别报告本次完成与下一次到期，后续使用相应对象的最新 ID 和版本。
- 每次逻辑写入使用唯一 `request_id`，同一请求重试必须使用完全相同的 ID 和参数。新动作或修正后的参数使用新 ID。新建时服务会检测同标题、同时间/到期日的重复，遇到 `DUPLICATE_FOUND` 查看返回的已有项；只有用户明确要额外一份时使用 `allow_duplicate: true`。
- 服务会写后读回核对，成功响应包含 `operation.verified: true`；可直接据此报告。`operation.replayed: true` 是此前成功结果的重放，若需要当前状态再读取。移动和重复实例修改可能改变 ID，后续使用最新返回值。
- `VERSION_CONFLICT` 表示事项已变更，先重新读取并比较用户意图，再决定是否针对新版本执行；不能只替换版本号盲目重试。超时或 `RESULT_UNKNOWN` 时调用 `get_operation`，并核对当前事项。`pending`/`uncertain` 均不证明失败，不能用新请求 ID 再创建一份。
- 处理 pending/uncertain 或维护日志时阅读 [高级操作](references/advanced.md)，核对后记录结论；不自动重写或清日志。
- 批量操作记录每项请求 ID 与成功/失败结果。遇到权限或连接问题时停止受影响写入，报告已完成部分，不擅自回滚用户数据。需要回顾最近操作时使用 `list_operations`，按需再读取记录详情。

## 能力边界与结果

MCP 支持日程和提醒的原生重复规则；使用 `recurrence`，不以大量单次事项模拟无限重复。不能操作参会邀请或修改/删除带参会者的会议，也不能编辑附件、子任务、旗标和定位提醒。

Skill 不会自行常驻执行。需要每日自动整理或定期汇报时，只有用户明确提出定时执行才创建对应自动化，并核实运行环境能连接这台 Mac 的 MCP。

结果简短列出实际完成的动作、事项标题、目标列表/日历和用户时区下的时间；规划建议与已写入结果应清楚区分。部分失败或有限查询范围必须说明，不输出不必要的内部 ID。
